# Исполнимая спецификация 0.6

Основные контракты проверяют `tests/compiler-dom.test.ts`, `tests/contracts.test.ts`, `tests/custom-hooks.test.ts`, `tests/server.test.ts` и браузерные сценарии.

## Состояние и вычисления

`useState(initial)` принимает значение или ленивый initializer. Функциональный setter получает текущее состояние; функциональное значение устанавливается через `setValue(() => fn)`. Сравнение — `Object.is`, включая `NaN` и знак нуля.

Чтение внешней реактивной переменной в callback получает актуальное значение. Локальная переменная обработчика — снимок:

```tsx
onClick={() => {
  const snapshot = count;
  setCount(value => value + 1);
  setTimeout(() => console.log(snapshot, count), 100);
}}
```

Два аргумента здесь могут различаться. Все синхронные записи внутри DOM-обработчика объединяются через `batch`. Сигнал читается сразу; зависимые DOM-обновления согласованно выполняются при завершении batch. Для пользовательских транзакций доступен `batch`.

Производные `const` с известными реактивными зависимостями поднимаются в `createMemo`. Неизвестные вызовы в таких выражениях вызывают `KANSO_PURITY`. `useMemo` — явное указание автора на чистое вычисление. Неподконтрольные компилятору побочные действия должны быть эффектами. Стандартные неизменяющие методы массивов/строк и Math кроме random входят в ограниченный список разрешённых операций.

`useReducer` поддерживает reducer, initial value и третий аргумент initializer. `useRef` возвращает стабильный нереактивный объект. Object ref заполняется при создании DOM и очищается при disposal.

## Эффекты

| Форма | Контракт |
| --- | --- |
| `useEffect(fn)` | Автоматически отслеживает синхронные чтения fn |
| `useEffect(fn, [])` | Один запуск после создания DOM владельца |
| `useEffect(fn, [a, b])` | Подписка только на deps; чтения внутри fn не расширяют список |

Deps сравниваются поэлементно через `Object.is`. Cleanup вызывается перед следующим запуском и при удалении владельца. На сервере эффекты не исполняются. Чтения после await не добавляются в подписку. Асинхронный effect callback не допускается типами; асинхронную работу запускают внутри обычного эффекта и отменяют в cleanup.

`useMemo(fn, deps)` и `useCallback(fn, deps)` используют те же правила deps. Callback может иметь стабильную идентичность и при этом читать актуальное состояние. Это отличается от замыканий React.

Hooks объявляются без условных ветвей в компоненте или скомпилированном `useX`. Тело компонента — setup; его повторные выполнения не являются механизмом обновления. Не вызывайте hooks из обработчиков.

## Пользовательские hooks

Именованная функция или const-функция `useX` компилируется как setup. Локальные hooks, именованные импорты с aliases, default-импорт именованного hook и переэкспорты сохраняют реактивность между модулями. Компилятор обрабатывает `.ts`, `.tsx`, `.js` и `.jsx`; готовый код в `node_modules`, `dist` и `dist-server` не компилируется повторно.

Аргумент, зависящий от состояния, props или производного значения, передаётся как живое чтение. Обычные аргументы вычисляются при вызове, функции остаются значениями. Параметры могут быть именованными или вложенными object/tuple patterns; object rest и defaults сохраняют живые чтения. Default инициализируется при первом чтении отсутствующего значения и затем сохраняется. Initializer `useState(initial)` потребляет значение при создании состояния; дальнейшее изменение аргумента не сбрасывает состояние.

Один терминальный `return` может возвращать scalar, tuple, объект или функцию. Пересчитывается чистое возвращаемое выражение, а не всё тело hook. Результат присваивается `const`; вложенная tuple/object-деструктуризация, включая rest, создаёт отдельную подписку для каждого поля. Локальные снимки внутри обработчика и live reads внешних bindings сохраняют обычный контракт Kanso. Эффекты hook принадлежат вызывающему компоненту и очищаются вместе с ним.

Async/generator hooks, условные вызовы, ранние returns, variadic-параметры и вычисляемые ключи и передача hook-функций как значений диагностируются. Для aliases используйте именованный import; namespace-вызовы hooks не поддержаны. Непроверяемые вычисления в return или живом аргументе требуют явного `useMemo`. Межмодульный ABI внутренний: hook и потребитель собираются одной версией Kanso; несобранная hook-библиотека получает `KANSO_HOOK_ABI`, а не молча устаревшее значение.

## JSX и идентичность

Сохраняются children, `className`, `htmlFor`, объектные styles, spreads, ref и обработчики. Числовые CSS-значения получают px, кроме стандартных unitless-свойств и CSS variables. События нативные: React SyntheticEvent не эмулируется. Для input/textarea `onChange` преобразуется в `onInput`.

`items.map(item => <Row key={item.id} item={item} />)` создаёт владельцев по ключам. Замена объектов с теми же ключами обновляет props существующих строк. Перестановка сохраняет DOM, состояние и фокус; удаление очищает ресурсы строки. Дубликат ключа — ошибка. Индекс доступен, но использовать его как ключ изменяемого списка нельзя.

Поддержан также callback с единственным `return JSX`. Вычисления и hooks в callback списка следует вынести в `Row`; сложные блоки выдадут `KANSO_LIST_BODY`. Фрагменты списка должны иметь явный key.

Деструктуризация первого параметра компонента, локальная деструктуризация props, defaults и rest остаются реактивными. Вложенные patterns поддерживаются; вычисляемые ключи требуют явного обращения к полю. Производные значения из `createStore` и объектов `useLoaderData`/`useForm`/`useParams`/`useLocation`/`useRevalidator` также отслеживаются.

Условные JSX и терминальные `if (...) return ...; return ...` становятся реактивными областями. Branch-specific setup переносится в дочерний компонент. Присваивание реактивному binding, экспорт живой локальной переменной и динамический JSX tag требуют явной другой формы и диагностируются.

Публичные lazy, Suspense и ErrorBoundary используют контракт Solid. ErrorBoundary принимает fallback с ошибкой и reset. Context Kanso передаёт getter: primitive, замена объекта и вложенные providers обновляют зависимых потребителей. useId согласует DOM ID сервера и клиента; ComponentProps, CSSProperties и RefObject предоставляют типы без зависимости от React. Подробности и контракт HMR — в [руководстве 0.4](dx.md).

## SEO

`@kanso/app/seo` предоставляет единый контракт метаданных для SSR, гидратации и навигации. Настройки, приоритеты, robots/sitemap и диагностика описаны в [SEO API](seo.md). Каждый запрос имеет отдельный collector; окончательный снимок сохраняется до disposal серверных владельцев. Повторные loader-запросы при гидратации не добавляются.

## SSR и данные

`defineRoutes` поддерживает статические пути, вложенные layouts, именованные параметры и терминальный splat. Идентификаторы уникальны. Более конкретный маршрут выигрывает у параметра. Optional segments не поддержаны и диагностируются.

Handlers располагаются в server entry / `.server.ts`. Такие модули и `@kanso/app/server`/`node` запрещены в клиентском графе. В транспорт попадают только результаты, которые можно представить JSON; произвольные функции, Map, циклы и BigInt не сериализуются.

На каждый запрос создаются context, loader snapshot и владельцы Solid. Loaders получают Request, params, context и AbortSignal. Сервер ждёт данные, рендерит HTML буферизованно и передаёт snapshot с build ID. Loader может вернуть/бросить Response для HTTP-ошибки или redirect.

Гидратация использует существующий DOM и исходный snapshot. Введённые до JavaScript значения input/textarea восстанавливаются и передаются установленным обработчикам. Это не полноценный replay всех ранних событий. Ошибка загрузки entry сохраняет SSR; ошибка самого render/hydrate не маскируется как успешная гидратация.

Навигация отменяет предыдущий fetch и проверяет последовательность до публикации ответа/redirect. Form отправляет native POST на URL страницы и возвращает 422 HTML при валидации. JavaScript использует тот же action через JSON: pending длится до завершения revalidation. Явно возвращённые values и ошибки из native POST передаются только соответствующей форме через bootstrap. Cleanup и смена URL отменяют незавершённую отправку; поздние ответы игнорируются. Ошибка revalidation сохраняет последний snapshot и повторяется отдельно от action. Контракты типов, формы и redirect описаны в [руководстве 0.5](web-apps.md).

HTML кешируется на сервере только при `cache: { public: true, ttlMs }`. Cookie/Authorization отключают общий кеш. Ключ включает build ID, URL и явно перечисленные vary headers. Success actions инвалидируют кеш; старый in-flight результат не возвращает удалённое поколение. Приложение отвечает за корректность декларации public и за внешнее хранилище кеша при нескольких процессах.

## Микрофронты

`@kanso/microfrontends` описывает доверенные удалённые Kanso-модули. Компонент входит в дерево владельцев Solid оболочки; отдельные корни гидратации не создаются. Оболочка предоставляет общий Router, Context и SEO. Точные версии runtime и совместимый диапазон контракта проверяются до исполнения удалённого кода. Обычный граф приложения без интеграции не получает federation runtime.

Каждое приложение и каждый SSR-запрос имеют свою сессию. Первый доступ закрепляет неизменяемый выпуск; bootstrap фиксирует версии, использованные модули и начальные данные. `prepareMicrofrontends()` до гидратации загружает все записанные модули. Ошибка оставляет SSR DOM для повторной попытки. Сессия, переданная в `App` извне, освобождается её создателем.

Приватные адреса берутся из `remoteSources` сервера, а не из клиентского bootstrap. Data/action transport и native формы передают проверяемые идентичности выпусков. Недоступная закреплённая версия не заменяется текущей; запись другим action автоматически не повторяется. HTML-кеш учитывает версии; sitemap сохраняет согласованные поколения частей при смене выпуска.

Удалённые маршруты получают пространство имён и точку подключения; `useRouteUrl()` учитывает её, а `routeUrl()` сохраняет прежнее поведение. SEO и ресурсы lazy-компонентов собираются после завершения SSR. Ошибки обязательных модулей возвращают `503`, таймауты — `504`, без кеширования. После гидратации ошибки виджета ограничены его границей. Отмена навигации и удаление владельца не позволяют поздним результатам восстановить закрытый раздел.

Новый совместимый выпуск не требует пересборки оболочки. Открытый документ использует прежний выпуск, поэтому старые клиентские и серверные артефакты сохраняются. Откат меняет текущий manifest; runtime-код по неизменяемому URL не переписывается. Настройка и жизненный цикл описаны в [руководстве](microfrontends.md).

## Web Workers и Service Workers

`@kanso/workers` создаёт native worker лениво при первом вызове задачи. Каждый вызов имеет идентификатор и отдельное завершение; `AbortSignal` отменяет его, поздние результаты игнорируются. Прерывание вычислений внутри worker кооперативное: задача проверяет signal и отдаёт управление очереди событий. `terminate()` останавливает native worker и отклоняет незавершённые вызовы. Передача буферов использует native structured clone/transfer без скрытого копирования состояния приложения.

`@kanso/workers/service` не регистрирует Service Worker при импорте или SSR. Регистрация, проверка обновления, активация и удаление вызываются явно. Активация не перезагружает документ и не удаляет кеши старых выпусков. `dispose()` освобождает только слушателей контроллера.

`service-runtime` кеширует только явно разрешённые статические GET-ресурсы. HTML/JSON, Kanso data/action endpoints, авторизованные запросы, `private`/`no-store` ответы и мутации обходят кеш. Версия из сборки отделяет кеши; ключ содержит полный URL. Единственное отдельно разрешаемое HTML-исключение — публичный self-contained offline fallback, отдаваемый только при сбое сети. Никакой очереди или автоматического повтора actions нет. Эти пакеты не вводят React, Solid или federation в worker.
