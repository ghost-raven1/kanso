# Миграция

Цель первого мигратора — собственный функциональный React + Vite код в поддерживаемом подмножестве Kanso. Проверка консервативна: неизвестная совместимость блокирует запись.

1. Установить зависимости исходного приложения, чтобы проверить реальный package graph.
2. Выполнить `kanso migrate --check` (или локальный CLI из README).
3. Разрешить все блокирующие диагностики; повторить проверку.
4. Выполнить `--apply`, проверить обычный diff.
5. Выполнить `npm install`, TypeScript, сборку и тесты пользовательских сценариев.

| Диагностика | Следующее действие |
| --- | --- |
| `REACT_DEPENDENCY` | Заменить/портировать библиотеку; адаптера React внутри Kanso нет |
| `DEPENDENCY_AUDIT` | Установить зависимость, чтобы проверить её graph и peers |
| `UNSUPPORTED_API` / `REACT_DOM` | Убрать/портировать API вне публичного контракта |
| `CLASS_COMPONENT` | Переписать класс в функцию |
| `STATE_SNAPSHOT` | Проверить несколько setter-вызовов и чтения после setter |
| `ASYNC_SNAPSHOT` / `CALLBACK_SNAPSHOT` | Зафиксировать нужный снимок локальной переменной либо принять live reads |
| `EFFECT_TRACKING` | Явно выбрать deps вместо React-эффекта после каждого render |
| `CUSTOM_HOOK` | Дать статически доступную локальную реализацию или портировать внешний hook |
| `KANSO_HOOK_*` | Использовать статические patterns/imports, const-результат и один терминальный return |
| `PATH_ALIAS` / `DYNAMIC_IMPORT` | Использовать tsconfig paths или статические resolve.alias; computed imports требуют ручного порта |
| `KANSO_PURITY` | Явно оформить чистое вычисление через useMemo либо действие через useEffect |
| `KANSO_LIST_KEY` / `KANSO_LIST_BODY` | Дать стабильный key, вынести setup строки в компонент |

Локальные пользовательские hooks проверяются через отдельные файлы и цепочки переэкспорта, включая aliases. Поддерживаются `.ts`/`.js`, scalar/tuple/object-результаты и вложенные вызовы hooks. Циклический или неизвестный контракт не считается доказанной совместимостью. Проверяются также мигрируемые реализации hooks, их зависимости и изменения snapshot-семантики; повторные вызовы возвращённых методов считаются потенциальными изменениями состояния и требуют проверки. Это консервативный анализ, возможны блокировки кода, который автор может безопасно портировать вручную.

Формы props и event types основаны на DOM/Solid. Сложные типы React не подменяются `any`; неподдерживаемые импорты типов требуют явного порта. Named/default React imports преобразуются, включая JSX Fragment и поддерживаемые qualified types. Entry `root.render(<App />)` становится `root.render(() => <App />)`, чтобы владелец создавался до JSX.

Изменения source/package/config сначала собираются в памяти. Ошибка анализа оставляет приложение неизменным. Перед записью проверяется отсутствие concurrent edits. Файлы заменяются через temporary+rename; при ошибке записи собственные записанные изменения откатываются. Это транзакция в рамках работы процесса, а не гарантия атомарности нескольких файлов при аварийном отключении питания.

Проверяется достижимый граф приложения. Неиспользуемый исходный файл не считается перенесённым. Поддержаны tsconfig paths/baseUrl/extends и статические resolve.alias Vite. Alias-резолверы произвольных плагинов, computed imports, классы и непроверенные внешние source workspaces автоматическим переносом не покрываются.

Мигратор не запускает React для неподдерживаемого кода и не меняет BRO PROKAT. CLI не устанавливает пакеты и не выполняет скрипты исходного приложения; это отдельный проверяемый шаг после diff.

## Изменения 0.4

Context поддерживает реактивный Provider.value; добавлены useId, ComponentProps, CSSProperties и RefObject. Вложенные параметры/результаты hooks и object/array rest переносятся без ручного уплощения. Анализ учитывает реальные bindings, поэтому одноимённая локальная переменная не считается состоянием другого компонента.

Ошибки содержат исходный код KANSO_*, строку/столбец и пример исправления. После установки зависимостей выполните kanso doctor. Пакеты и скомпилированные hooks обновляются одной версией; не смешивайте ABI разных релизов. [Примеры, HMR и шаблоны](dx.md).

## Веб-слой 0.5

Изменений существующего приложения не требуется. Для native POST замените ручной fetch на `useForm`/`Form`, возвращайте проверенные `values` вместе с `errors`, а на странице привяжите `value={form.values.name ?? ''}`. Не возвращайте целиком FormData: пароли и другие непредназначенные для отображения сведения должны оставаться на сервере.

`pending` теперь включает revalidation. Ошибка обновления доступна отдельно через `useRevalidator`; повторный refresh не повторяет сохранение. При смене URL pending-запрос формы отменяется, её состояние очищается. Старые `useForm<T>(routeId?)` и `Record<string, RouteHandlers>` поддерживаются.

Можно постепенно перейти на `defineRouteHandlers`, `routeUrl`, `RouteParams` и `LoaderData`. Серверные типы импортируются через `import type`; runtime-import по-прежнему запрещён. Новые преобразования мигратора для роутинга или форм в 0.5 не добавлены. См. [полный контракт](web-apps.md).
